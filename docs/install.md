# 安装

[HFile](../README.md) › [文档](README.md)

设置文件 `config.toml` 里还没有 `secret_key` 时（比如程序第一次运行时自动新建的那个），程序以安装模式启动：整个网站只有安装页面 `/install/`，别的地址都跳过去，接口返回 503。

1. 运行程序（`hfile`；从源码是 `python -B hfile.py`，或 `python -B manage.py runserver`）。它会打印安装页面的完整地址和**安装口令**，口令也存在设置文件旁边的 `install-token.txt` 里（权限 600，只有这个系统用户能读）。网站还没有管理员时，谁先打开安装页谁就能当管理员，所以要输入只有服务器上的人才看得到的口令；打印出来的地址已经带着它。
2. 安装页面分四步，一次显示一步：安装口令、数据库、网站、第一个管理员。带 * 的是必填项，没填完「下一步」点不了；点了以后程序先检查这一步填得对不对（`/install/check/`），对了才往下走，不对就标在那一项旁边。上面的步骤条里，走过的步骤可以点回去改。
   - 安装口令：打开打印出来的地址时已经填好了。
   - 数据库：先选 SQLite 还是 MySQL，下面只显示选中那种的设置。「测试连接」用填的设置连一下，说出找到了什么，什么都不留下：不建库；SQLite 要试着写一下，新建的文件和文件夹试完就删掉。这一步的「下一步」也先做同样的测试。事先在 `config.toml` 里填过的已经填好了（密码除外，谁都能打开这个页面）。
     - SQLite：数据库文件的路径，默认 `hfile.sqlite3`，相对路径从 `config.toml` 所在的文件夹算起。文件夹不存在会建好；文件由向导新建，权限 600，用 WAL 模式。已经有这个文件的话，里面不能有别的程序的表。
     - MySQL：地址、端口、库名、用户名、密码（可以空着）。库不存在就自动创建（`utf8mb4`，`utf8mb4_0900_ai_ci`），这要用户有建库的权限；已经存在的库里不能有别的程序的表。只支持 MySQL 8.4 以上（MariaDB 不行）。用宝塔、1Panel 的话，先在面板里建好库和用户，再把它们填进来。要求加密、校验证书的设置（`[database]` 的 `tls`、`ca`，见[「设置文件」](configuration.md)）页面上没有，要事先写进 `config.toml`：测试连接和安装都照它们连接。
   - 网站：网站名称；网站地址（写进 `[site] url`，默认是浏览器打开安装页用的地址，由页面上的 JS 读浏览器自己的地址，比程序看到的准）；允许访问的域名或 IP（写进 `allowed_hosts`，127.0.0.1、localhost 和网站地址里的域名自动加上）；反向代理的层数（写进 `[server] proxies`：请求里有 `X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`、`X-Real-IP`、`Forwarded` 之一，或者浏览器用的是 https 而程序收到的是 http 时，默认选 1 层）；后台地址（留空就随机生成 12 个字符）。
   - 第一个管理员：用户名、密码、再输一次密码。它是超级管理员，能进管理页和后台。

   没有 JavaScript 时四步一起显示，没有「测试连接」，表单照样能交。
3. 点「开始安装」：程序把整张表单再检查一遍，再建表（和升级是同一套流程，建表失败会把库恢复成空的），建管理员，写网站名称，最后把密钥、数据库、网站的设置和反向代理的层数写进 `config.toml`（权限 600；另一种数据库的设置、`[server]` 的地址和端口、`debug`、文件夹和 `[upgrade]` 保持原样），删掉口令文件。`config.toml` 写不进去时（比如文件夹只读），完成页列出文件的全部内容，照着写进去再启动。哪一项不对，页面上就标在哪一项旁边。同时只能有一个安装在进行，两个标签页一起点也只装一次。
4. 完成页显示后台的完整地址，只显示这一次。程序自己重启、读入新的设置（见[「运行」](deploy.md)的两个进程），页面等网站起来后提示可以打开了。用别的 Web 服务器（比如 gunicorn）加载 `config.wsgi` 时，要手动重启一次。

安装页面的表单不做 Django 的 CSRF 检查。装好之前程序还不知道自己对外的地址：放在结束 https 的反向代理（Caddy、Nginx、宝塔、1Panel 等）后面时，浏览器发来的来源是 `https://…`，程序看到的却是 `http://…`，表单就交不上去。防止别的网站替人提交这个表单的，是安装口令：别的网站拿不到它，没有它表单什么也不做。`/install/check/` 也一样：口令不对时别的项一概不看，更不会去连填进来的数据库地址。

装好以后 `config.toml` 里有了密钥，安装页面就没有了（404）。向导不接管已经装过 HFile 的数据库：库里有账号时直接拒绝，提示把原来的 `config.toml` 放回去。要重新安装，换一个空数据库（SQLite 换一个新的文件名），并清空 `secret_key`（或者删掉 `config.toml`）。

也可以不用网页安装：自己在 `config.toml` 里填好 `[database]` 和 `[site] secret_key`，再 `hfile upgrade` 建表、`hfile createsuperuser` 建管理员。SQLite 的数据库文件不管是哪个命令先建出来的（`check`、`migrate`、`backup` 也一样），权限都是 600。还没装好时，除了 `serve`、`runserver`、`check`、`collectstatic` 和帮助，别的命令都会提示先安装。

后台的地址是 `config.toml` 里的 `admin_path`；没设时由 `secret_key` 算出一个固定的随机地址（换了密钥就跟着变）。地址只能用字母、数字、`-` 和 `_`，不能是 `admin`，也不能和网站自己的地址（`api`、`manage`、`static`、`media` 等）重名，写错了程序不启动。`/admin/` 永远是 404。
